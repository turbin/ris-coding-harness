## Recurring patterns

1. **RED 证据全缺失**（10/10 次）：所有任务直接进入实现，无一先写失败测试/复现脚本。
   → 归因（机制）：协议（SKILL.md §7 Coder contract）要求 RED，但在「外部机器判定
     （verify.sh）提供测试」的场景下出现协议空洞——agent 把外部 check 当作测试本身，
     协议没有定义「评估场景下 RED 证据的最小形式」，也没有强制「本地先红后绿」。
   → 这是协议执行缺口，不是「这次没做好」：规则层也没有对应检查项。
   → 提案 P1（L1 规则回写）+ L2 候选（SKILL.md 定义 RED 证据最小形式，Phase 4）。

2. **未验证的假设直接进实现**（2 次，MAJOR/correctness）：02 假设 `dict.move_to_end`
   存在（实为 `OrderedDict` 方法）；03 假设 `if not text` 覆盖纯空白输入（实不覆盖）。
   → 归因（机制）：实现前没有「探针验证 API 存在性与签名」的检查项，也没有
     「边界输入清单先行」的测试规则；RED 缺失使这些假设只能被事后 verify 暴露。
   → 提案 P2、P3（L1 规则回写）。

3. 【观察项，不足提案阈值】grep 式约定检查对文档文本敏感（1 次，MINOR/convention）：
   07 的 docstring 字面提到禁用术语被 `grep` 误命中。
   → 1 次出现不足 2 次提案阈值，按 §4.3/§8.2 纪律**不作为正式提案**；记录为
     L3 观察（verify.sh 属 protected 资产，建议人工改为匹配 `import`/调用模式
     而非裸词）。若后续再现，升格为 L1 规则候选。
